# 项目概述与范围

> 说明：本文件描述的是项目目标范围与设计口径，不是当前实现完成度说明。实际已完成项、未完成项与当前 baseline 请以 `doc/process/03-current-progress-dashboard.md` 和 `doc/process/04-baseline-closure.md` 为准。

## 1. 项目名称

高校/企业心理测评与预警系统

## 2. 项目定位

本系统面向高校心理中心、辅导员体系、企业 HR 或 EAP 场景，提供心理测评任务下发、在线答题、自动评分、报告生成、风险预警、咨询预约、干预跟踪和群体分析等能力。

系统目标不是单纯的在线问卷，而是形成完整闭环：

量表配置 -> 测评任务 -> 在线作答 -> 自动报告 -> 预警识别 -> 咨询干预 -> 复测/结案 -> 统计分析

## 3. 术语定义

- 被测者：参与心理测评的学生或员工用户
- 预警：系统根据量表结果或高危题项识别出的关注或高风险事件
- 干预：围绕预警对象开展的咨询、访谈、转介、复测等处理行为
- 复测：用户在首次测评后再次参与同一量表或关联量表的测评
- 实名测评：测评结果可关联到具体用户身份的测评模式
- 匿名测评：测评结果默认不直接关联到具体个人身份的测评模式
- 群体报告：面向咨询师、管理员或管理人员的群体统计与分析报告

## 4. 建设目标

### 4.1 提高测评组织效率

- 支持按组织或个人分配测评任务
- 支持批量开展普查、筛查和复测

### 4.2 建立自动分析能力

- 测评提交后即时完成自动评分
- 生成个人系统报告和群体统计结果

### 4.3 实现风险预警

- 自动识别高风险或关注对象
- 将风险结果纳入后续跟踪流程

### 4.4 支撑咨询与干预闭环

- 支持咨询师补充报告
- 支持咨询预约、干预记录、状态流转和结案

## 5. 适用场景

### 5.1 高校场景

- 新生心理普查
- 学期心理筛查
- 特定群体专项测评
- 重点学生跟踪和复测

### 5.2 企业场景

- 员工心理普查
- 高压岗位筛查
- 部门压力测评
- 企业 EAP 跟踪服务

## 6. 终端范围

系统需支持以下终端：

- PC Web 管理端
- 原生手机 App 用户端
- 微信小程序用户端

## 6.1 最终技术栈结论

当前项目最终明确的技术栈如下：

- 后端：Kotlin + Spring Boot + Spring Security
- 认证与权限底座：`auth-starter`
- 数据库：PostgreSQL
- 缓存：Redis
- 管理端前端：React + TypeScript
- Android：原生 Kotlin
- iOS：原生 Swift
- 微信小程序：原生微信小程序
- 文件存储：本地文件服务或对象存储

## 6.2 最终架构结论

当前项目最终明确的架构如下：

- 整体采用前后端分离架构
- 后端当前阶段采用单体应用 + 模块化分层实现
- 管理端为 PC Web 独立前端
- 用户端采用原生 Android App、原生 iOS App 和微信小程序三端接入
- 三类前端统一复用后端核心业务 API
- 用户、认证、权限、组织等基础能力复用 `auth-starter`
- 心理业务能力作为独立业务模块实现，包括量表、任务、答题、报告、预警、干预、预约、通知、统计

## 7. 角色范围

系统主要角色包括：

- 被测者
- 咨询师
- 测评管理员
- 学校或企业管理人员
- 系统管理员

## 8. 范围边界

### 8.1 本项目重点建设内容

- 量表管理
- 测评任务管理
- 在线答题
- 自动评分与报告
- 群体报告与统计分析
- 预警与干预跟踪
- 咨询预约
- 多角色权限控制

### 8.2 基础能力复用范围

用户管理基于 `auth-starter` 基础工程扩展实现，复用其已有能力：

- 登录注册
- JWT 认证
- 用户、角色、权限管理
- 组织与租户能力
- 审计日志能力

### 8.3 当前明确不做的范围

为控制项目边界，当前阶段默认不纳入以下建设内容：

- 高校完整学籍管理系统
- 企业完整人事管理系统
- 医疗诊断与电子病历系统
- 主动心理干预推荐引擎
- 外部医院或第三方咨询机构的深度业务协同平台
- 完整 CRM 或工单平台替代能力

## 9. 数据隐私与安全边界

系统涉及心理测评和个人敏感信息，后续设计与实现需重点关注：

- 遵循最小必要原则采集和展示数据
- 对敏感个人信息做脱敏和权限隔离
- 对敏感访问、导出和修改行为保留审计日志
- 结果展示强调测评参考属性，不替代专业医疗诊断

在中国场景下，建议后续设计时参考：

- 《中华人民共和国网络安全法》
- 《中华人民共和国个人信息保护法》
- 《中华人民共和国数据安全法》

## 10. 业务闭环定义

本项目当前要求具备如下完整闭环：

1. 管理员导入或配置量表
2. 管理员按组或按个人分配测评任务
3. 被测者完成在线作答
4. 系统即时生成系统报告
5. 系统识别风险并生成预警
6. 责任人接单并跟进
7. 咨询师预约或执行咨询
8. 记录咨询、干预、转介或复测
9. 最终结案或持续跟踪
10. 沉淀群体报告和统计分析结果
