# 工程审查与改进清单（2026-04-11）

## 1. 总体结论

当前工程已经具备继续开发和演示的 baseline：

- 管理端已形成主链路
- 用户侧 Web 已具备基础闭环
- 后端主业务链路、导出、通知、审计、预约、统计均已成型
- 当前前后端构建与测试基线已恢复稳定

但从“产品级交付”和“长期维护”的角度看，仍需持续补强：

- 权限边界与敏感数据访问控制
- 国际化闭环与异常处理统一
- 集成测试与安全测试覆盖
- 构建、发布、CI 与环境校验
- 文档一致性与编码质量
- 多端扩展能力

## 2. 高优先级风险

### P0：敏感接口需要持续保持显式授权

重点接口包括：

- 报告详情
- 答题保存 / 提交
- 报告导出
- 预警认领 / 指派
- 预约创建 / 咨询排班

当前状态：

- 关键接口的 `@PreAuthorize` 与服务层校验已补齐一轮
- 已新增多组 WebMvc / 安全契约测试

后续建议：

- 新增接口默认执行“显式授权 + 服务层兜底”的双保险
- 不再依赖“全局配置默认拦截”来表达业务权限

### P0：报告、导出、审计链路仍应持续做权限回归

涉及：

- `backend/src/main/kotlin/org/sainm/psy/report/api/ReportController.kt`
- `backend/src/main/kotlin/org/sainm/psy/report/service/ReportService.kt`

当前状态：

- 服务层授权判断已补齐
- 普通用户读取自己的报告、管理员读取授权范围内报告的能力已覆盖
- 相关安全测试已补入

后续建议：

- 继续补跨机构、跨角色、跨用户边界测试
- 对导出、审计 drilldown、报告详情页等复用路径继续复核

## 3. 中高优先级改进项

- `MessageSource` + `Accept-Language` locale 解析

- 在部署文档里写清环境变量要求

## 4. 中优先级工程改进

### P2：异步导出仍然偏内存态

涉及：

- `backend/src/main/kotlin/org/sainm/psy/export/service/ExportJobStore.kt`

当前状态：

- 已增加内存任务数与文件大小上限保护
- 已支持异步任务状态查询与下载
- 已支持 locale 在异步导出链路中的透传

后续建议：

- 将任务状态持久化到 DB 或 Redis
- 将导出文件落到对象存储、文件存储或临时目录
- 增加过期清理、失败重试、下载鉴权与大文件策略

### P2：前端 token 存储方案仍需评估

涉及：

- `admin-web/src/auth/token.ts`

当前状态：

- access token / refresh token 仍存储于 `localStorage`

风险：

- 如果前端存在 XSS，token 可能被读取

建议：

- 评估迁移到 `httpOnly secure cookie`
- 若继续使用 `localStorage`，需要加强 CSP、XSS 防护、token 轮换与异常审计

### P2：文档与实际技术栈需要持续同步

当前状态：

- 已修复多份乱码文档
- 已补齐 README / 交付文档 / 国际化指南的一部分

后续建议：

- 持续清理剩余历史乱码文件
- 保持 README、过程文档、交付清单与真实代码一致
- 明确技术栈版本、启动方式、路由与环境变量
