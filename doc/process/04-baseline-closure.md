# Baseline 闭环说明

## 1. Baseline 目标

当前 baseline 的目标不是“最终产品全部完成”，而是形成一条：

- 可以演示
- 可以继续开发
- 可以作为后续迭代基准

的稳定工程闭环。

## 2. 当前 baseline 包含什么

### 2.1 认证与会话闭环

- 用户名密码登录
- access token / refresh token 刷新
- 退出登录
- 当前用户信息读取
- 会话守卫
- 会话详情页
- 认证审计页

### 2.2 管理端主链路闭环

- 量表管理
- 测评任务管理
- 答题与评分
- 报告生成与查看
- 风险预警处理
- 干预记录
- 预约基础能力
- 通知基础能力
- 群体报告与统计看板
- 报告导出

### 2.3 用户侧 Web 闭环

- 我的任务
- 问卷作答
- 草稿恢复
- 我的报告
- 通知回流
- 预约创建
- 会话详情

### 2.4 文档与过程闭环

- 需求、Prompt、过程文档可追踪
- 交付清单已整理
- 工程审查结论已整理
- 国际化接入指南已整理

## 3. 当前验证结果

截至 2026-04-11，已确认：

- [admin-web](/d:/source/lx-boot/admin-web) `npm run build` 通过
- [backend](/d:/source/lx-boot/backend) `./gradlew test --rerun-tasks` 通过

这意味着当前 baseline 已经具备“可构建、可测试、可继续开发”的基础条件。

## 4. 当前 baseline 不包含什么

以下内容不应被误认为已在 baseline 内完成：

- Android 原生端实现
- iOS 原生端实现
- 微信小程序实现
- 深度统计分析与复杂图表
- 完整 CI/CD 与自动化发布
- 大文件场景的成熟导出存储方案

## 5. 当前仍建议继续补强的点

- refresh token 失败后的完整重登 UX
- 会话失效提示与恢复体验
- PDF 字体兜底与跨环境兼容性
- 预约 / 咨询闭环细节
- 更完整的测试覆盖
- 更稳定的部署与环境约束

## 6. 可以视为已锁定的基线

建议把下面这些内容视为当前不可随意回退的基线：

- Kotlin + Spring Boot 单体模块化后端结构
- `auth-starter` 统一认证与审计底座
- React 管理端与用户侧 Web 入口
- 当前数据库模型与 API 组织方式
- 当前导出与通知的主链路
- 当前中英双语国际化基础设施

## 7. 下一步建议

在当前 baseline 之上，建议优先继续推进：

1. 产品级收口：会话 UX、预约咨询、报告阅读与导出体验。
2. 工程级收口：CI、部署、自动化检查、环境文档。
3. 能力级扩展：更深统计分析、多端应用。
