确认结论：
- 测试分层采用 `单元测试 -> 集成测试 -> 接口测试 -> UI 测试 -> 性能测试 -> 安全测试`
- 后端主链路应优先完成自动化验证，重点覆盖量表、任务、答题、评分、报告、预警
- `auth-starter` 集成必须纳入集成测试，重点验证登录态、角色菜单、接口鉴权和数据范围控制
- React 管理端需要覆盖主流程页面联调、权限可见性、敏感字段脱敏展示和关键操作二次确认
- Android、iOS、小程序暂不进入第一阶段代码主目标，但后续应预留兼容性测试要求
- 发布前必须完成数据库初始化验证、权限回归、核心链路人工验收和关键日志校验

联调顺序建议：
1. 后端数据库初始化与基础配置验证
2. 后端主链路接口联调
3. React 管理端接入登录态与权限菜单
4. React 管理端接入量表、任务、报告、预警接口
5. 主链路回归测试与问题修正
6. 第二阶段能力再逐步接入预约、通知、统计与导出

CI/CD 建议：
- 后端：执行 `gradle test`、静态检查、构建产物校验
- React 管理端：执行 `npm run lint`、`npm run test`、`npm run build`
- 数据库：校验 DDL、初始化脚本和种子数据脚本可执行性
- 后续移动端接入后，再增加 Android/iOS 构建检查与小程序构建校验

兼容性与专项测试建议：
- 浏览器：Chrome 最新版优先，兼容 Edge
- Android：覆盖主流版本与弱网场景下的答题暂存恢复
- iOS：覆盖主流系统版本、隐私授权弹窗和审核敏感项
- 小程序：覆盖不同基础库版本、订阅消息与分包加载
- 安全：重点验证未授权访问、越权访问、敏感数据脱敏、导出权限、输入校验
- 性能：重点验证任务列表、答卷提交、自动评分与预警识别
