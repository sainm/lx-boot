# 页面与模块设计

## 1. 页面设计目标

系统需要根据角色展示不同页面，并兼顾管理端、原生手机 App 和微信小程序端的使用体验。

建议在页面设计时同时输出：

- 页面流程
- 页面模块组成
- 页签配置
- 页面与角色权限映射

- 数据卡片

## 8. 移动端与小程序设计建议

- 答题流程采用纵向单列布局
- 减少复杂图表堆叠
- 优先保证任务、答题、报告、预约四类核心功能
- 报告页图表可简化，但核心数据必须保留
- 原生 App 优先保证流畅交互和本地设备适配
- 小程序优先保证轻量和快速触达

## 9. 页面导航结构建议

- 用户端 App：首页 / 我的任务 / 在线答题 / 个人报告 / 我的预约 / 消息通知
- 小程序端：首页 / 我的任务 / 在线答题 / 个人报告 / 我的预约
- 咨询师端：工作台 / 预警列表 / 个体详情 / 预约管理 / 咨询记录
- 管理端：统计看板 / 量表管理 / 任务管理 / 群体报告 / 预警管理
- 系统管理端：用户组织 / 角色权限 / 系统配置

## 11. Session And Auth Audit Pages

### 11.1 会话详情页 `/session`

- 入口角色：`ASSESSMENT_ADMIN`、`COUNSELOR`、`ORG_MANAGER`、`SYS_ADMIN`
- 核心信息：
  - 当前用户与角色
  - 当前会话来源与健康状态
  - access token / refresh token 到期时间与剩余时间
  - 最近 token 同步时间
- 主要操作：
  - 手动刷新会话
  - 复制诊断信息

### 11.2 认证审计页 `/auth-audit`

- 入口角色：`ORG_MANAGER`、`SYS_ADMIN`
- 核心信息：
  - 登录日志
  - 安全事件
  - 当前筛选条件
- 主要操作：
  - 按 `principal`、`result` 查询登录日志
  - 按 `eventType` 查询安全事件
  - 分页查看上一页 / 下一页

## 12. 移动端会话状态与失效处理

### 12.1 用户侧会话状态页

- 适用终端：Android、iOS、微信小程序
- 入口角色：普通被测者用户
- 核心信息：
  - 当前登录用户
  - access token / refresh token 剩余时间
  - 最近一次 token 同步时间
- 主要操作：
  - 手动触发会话刷新
  - 查看登录状态是否有效

### 12.2 登录失效处理

- 移动端统一要求：
  - 本地恢复登录态
  - `401 -> refresh -> retry`
  - refresh 失败后回登录页
- 弱网场景下需要保证：
  - 答题内容优先暂存
  - token 刷新失败时不直接丢失本地答题状态
  - 恢复登录后允许继续答题或重新提交

### 12.3 管理审计边界

- `/auth-audit` 属于管理端安全审计页面
- 移动端与小程序不实现管理审计页面
- 移动端仅保留用户侧会话信息查看与轻量调试能力
