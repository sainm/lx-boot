# 心理测评微信小程序实施 Prompt

## 使用说明

将下面代码块中的内容完整复制给 Codex、GitHub Copilot 或其他代码代理，用于设计、实现和验证心理测评微信小程序。该 Prompt 以被测者业务为主，同时覆盖微信登录、订阅消息、隐私合规、中日英三语和弱网恢复。

```text
请为当前心理测评系统设计并实现微信小程序端。

这不是静态演示或页面原型。小程序必须连接现有真实后端 API，与 Web、Android 和后续 iOS 共用业务数据、认证规则、任务状态、评分结果、预约、通知和权限模型。

目标业务闭环：

微信登录/账号绑定 → 隐私授权 → 首页待办 → 查看任务 → 答题与保存 → 幂等提交 → 查看个人报告 → 接收通知 → 预约咨询 → 查看预约状态 → 个人资料与账号安全。

一、实施原则

- 优先复用现有后端 API，不复制一套小程序专用业务逻辑
- 不使用假数据、静态 JSON 或本地模拟代替真实接口
- 不在小程序中实现可信评分、权限判断或风险规则，最终判定必须由后端完成
- 不改变 Web、Android 已使用的 API 契约；如确需扩展，保持向后兼容
- 所有敏感接口必须由后端验证用户、租户、对象所有者和业务状态
- 小程序仅承载被测者可见业务，不暴露内部预警、干预、稳定键或数据库 ID
- 符合微信小程序审核、用户隐私保护和心理健康业务合规要求

二、技术方案

优先评估当前仓库和团队技术栈后，在以下方案中选择维护成本最低的一种：

- 微信小程序原生：TypeScript + WXML + WXSS
- Taro + React + TypeScript

选择前先说明依据。不要为了跨端而引入与现有工程不兼容的重型框架。

工程至少包含：

- 环境配置：开发、测试、生产
- API Client
- Token 与会话管理
- 页面路由
- 状态管理
- 国际化
- 主题与设计 Token
- 错误处理
- 埋点和诊断日志
- 单元测试
- 小程序自动化测试
- 构建和发布说明

三、登录与账号绑定

实现真实微信登录流程：

1. 使用 `wx.login` 获取临时 code
2. 将 code 发送到后端，由后端完成微信身份交换
3. 已绑定账号直接登录
4. 未绑定账号进入安全绑定流程
5. 支持学校账号、用户名密码或后端允许的其他身份验证方式
6. 登录成功后由后端签发访问 Token 和刷新 Token
7. 记录设备类型、设备标识、客户端版本和会话信息

要求：

- AppSecret、会话密钥和服务端凭据禁止放入小程序代码
- 不信任客户端传入的 openId、unionId、角色、userId 或 tenantId
- Token 不得输出到日志或错误页面
- 正确处理 Token 过期、刷新、撤销、账号禁用和绑定冲突
- 退出登录必须调用后端注销并清理本地敏感信息
- 不允许通过切换账号读取上一账号的草稿或通知
- 对敏感本地数据设置最小保存期限

四、隐私授权与合规

首次使用时展示清晰的隐私说明：

- 收集哪些信息
- 信息用途
- 是否实名
- 匿名测评的匿名范围
- 报告可见范围
- 高风险结果可能触发的处理流程
- 数据保存和删除方式
- 联系方式和紧急求助提示

要求：

- 在真正需要时再申请用户信息、通知等权限
- 拒绝非必要权限后仍能使用基础功能
- 隐私政策、用户协议和知情同意版本可追踪
- 不使用诱导授权或默认勾选
- 心理危机场景不能只提供自动化结果，必须显示人工帮助和紧急联系方式
- 不在分享卡片、通知标题或系统截图中暴露敏感测评结果

五、页面和信息架构

至少实现：

1. 启动与会话恢复
2. 登录/绑定账号
3. 隐私政策与知情同意
4. 首页
5. 我的测评任务
6. 答题页
7. 提交确认和提交结果
8. 我的报告
9. 报告详情
10. 咨询师与可预约时间
11. 我的预约
12. 通知中心
13. 个人资料
14. 设置、语言和账号安全
15. 通用加载、空状态、错误、无权限和离线页面

首页优先展示：

- 当前最需要完成的任务
- 即将截止的任务
- 最近报告
- 即将到来的预约
- 未读通知

不要把管理端复杂表格和菜单直接缩小搬到小程序。

六、答题流程

答题页需要适合手机和单手操作：

- 一次聚焦一个问题
- 显示题号、总题数和进度
- 支持上一题、下一题和题号导航
- 支持单选、多选、文本、滑块、矩阵、选项加文本
- 必答题提供温和、明确的提示
- 选项点击区域足够大
- 不使用容易诱导答案的颜色或措辞
- 显示最近保存时间和同步状态
- 支持后端草稿与本地临时草稿恢复
- 任务版本、答卷版本发生冲突时提供明确恢复方案

必须由后端强制执行：

- 任务是否分配给当前用户
- 开始时间和结束时间
- 是否允许保存
- 是否允许重测
- 是否允许超时提交
- 量表版本
- 答案合法性
- 幂等提交

提交要求：

- 每次逻辑提交生成稳定的 Idempotency-Key
- 网络超时后先查询提交结果，不立即生成新 Token 重复提交
- 提交过程中禁用重复点击
- 成功后清除对应账号和任务的本地草稿
- 匿名任务完成后不进入个人报告或个人风险页面
- 已完成且不允许重测的任务不能重新进入空白答题页

七、报告

个人报告至少支持：

- 量表名称和版本
- 测评时间
- 总分和维度分
- 风险等级
- 结果解释
- 建议
- 趋势或维度图表
- 数据使用和免责声明

要求：

- 图表之外必须提供文字说明
- 风险不能只通过颜色表达
- 不显示内部预警 ID、处理优先级或数据库字段
- 报告查询必须验证本人权限
- 截图和转发前提示敏感信息风险
- 默认禁止把具体心理结果放入分享卡片标题
- 匿名测评不显示个人报告入口

八、预约

实现：

- 咨询师列表
- 可预约时间
- 创建预约
- 查看预约详情
- 取消预约
- 改期（后端支持时）
- 查看已确认、已完成、已取消和已失约状态

要求：

- 防止重复占用名额
- 显示时区和完整日期时间
- 创建成功后刷新可用名额和预约列表
- 预约变更通过站内通知和订阅消息发送
- 不在订阅消息中暴露敏感测评详情

九、通知与微信订阅消息

实现站内通知，并接入微信订阅消息：

- 任务分配
- 任务即将截止
- 报告生成
- 预约创建或变更
- 必要的服务提醒

要求：

- 在合理业务时机请求订阅授权
- 记录用户是否同意对应模板
- 模板 ID 由环境配置提供，不写死在代码
- 后端负责发送、重试、投递状态和审计
- 小程序打开通知后跳转到正确业务页面
- 支持通知目标路径版本兼容
- 站内消息已读与点击状态正确回传
- 预警和敏感信息不得使用过度暴露的通知文案

十、中日英三语

支持：

- 简体中文：`zh-CN`
- 日语：`ja-JP`
- 英语：`en-US`

覆盖：

- 页面标题和导航
- 按钮、表单和校验
- 任务和答题提示
- 报告
- 预约
- 通知
- 隐私政策入口
- 错误、空状态和离线提示
- 日期、时间、数字和百分比

要求：

- 禁止在 WXML、TS、TSX 或业务代码中硬编码自然语言
- 三种语言 key 完全一致，并由测试验证
- 语言选择持久化，并随 API 请求发送
- 切换语言不能丢失当前答题进度
- 处理日文和英文变长后的按钮、卡片和导航布局
- 建立心理学专业术语表，专业译文标记业务审核状态

十一、视觉和可访问性

视觉方向：

- 专业、温和、可信、克制
- 使用低饱和蓝色或蓝绿色
- 大面积浅色背景
- 风险色仅用于必要区域
- 避免娱乐化、游戏化和高刺激动画

要求：

- 适配常见手机尺寸和安全区域
- 主操作可单手完成
- 触控区域不小于合理移动端尺寸
- 文字和背景满足可读性
- 不能只依赖颜色传递状态
- 支持系统字体缩放情况下的基本可用性
- 加载骨架不能造成频繁闪烁
- 尊重用户减少动画的偏好（在平台能力允许范围内）

十二、网络、缓存和错误恢复

处理：

- 首次加载
- 弱网
- 离线
- 请求超时
- Token 过期
- 服务端业务冲突
- 版本冲突
- 重复提交
- 部分数据加载失败
- 后端维护

要求：

- GET 请求可在安全范围内缓存
- 心理报告、答案和 Token 不得进入不受控的长期缓存
- 本地草稿必须按用户和任务隔离
- 恢复草稿时验证量表版本和答卷版本
- 错误提示使用业务语言，不直接显示堆栈和内部异常
- 每个失败状态提供可执行的下一步

十三、性能

- 分包和按需加载
- 控制首包大小
- 图片压缩并按需加载
- 避免重复请求
- 合理使用缓存
- 长列表分页
- 图表按需加载
- 避免频繁 setData 或无效渲染
- 在低端设备和弱网下验证答题流程

十四、测试与验收

必须执行：

- TypeScript 类型检查
- 单元测试
- API 契约测试
- 中日英资源一致性测试
- 微信开发者工具构建
- 真机预览
- 小程序自动化测试
- 弱网和离线测试
- 权限与隐私测试
- 包体积检查

至少验证：

1. 新用户使用微信登录并绑定现有账号。
2. 中文、日语、英语分别完成登录、答题、报告查看和预约。
3. PHQ-9、GAD-7 和至少一种复杂题型量表可完整作答。
4. 中途退出后恢复后端草稿和本地未同步内容。
5. 截止前、截止后允许提交、截止后禁止提交三种边界正确。
6. 网络超时重试不会生成重复结果和报告。
7. 匿名任务不出现个人报告和个人风险信息。
8. 订阅消息跳转到正确任务或预约。
9. 切换账号后不能读取上一账号的草稿、报告或通知。
10. 无权限对象 ID、跨租户对象 ID 均被后端拒绝。

十五、交付方式

先输出：

- 当前后端 API 与小程序需求映射表
- 可直接复用、需要扩展和缺失的接口
- 页面和路由清单
- 数据安全方案
- 微信平台配置清单
- 实施阶段和测试计划

然后直接实现。

完成后报告：

- 新增和修改的文件
- AppID、域名、模板消息等需要人工配置的项目，但不要写入真实密钥
- 已验证业务 Case
- 构建、自动化和真机验证结果
- 未完成能力和剩余风险
- 是否达到可演示、可体验版、可审核、可发布四个等级

只有真实 API、登录、答题、提交、报告、预约、通知、隐私和异常恢复全部接通，才算小程序业务闭环。
```
