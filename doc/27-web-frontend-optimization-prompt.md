# 心理测评 Web 前端优化 Prompt

## 使用说明

将下面代码块中的内容完整复制给 Codex、GitHub Copilot 或其他代码代理，用于优化管理端、咨询师工作台、组织管理端和被测者 Web。该 Prompt 要求优先修复业务流程断点，再统一视觉与交互。

```text
请全面优化当前心理测评系统的 Web 前端，包括管理端、咨询师工作台、组织管理端和被测者端。

这不是简单调整颜色或组件样式，而是从真实心理测评业务、操作效率、心理安全感、移动端体验和中日英国际化角度，重新审查并优化页面结构、交互流程和视觉设计。

技术栈保持现有 React、TypeScript、Ant Design、React Query、ECharts 和现有路由/API，不要无理由更换框架，也不要破坏后端接口契约。

一、总体设计目标

前端需要达到：

- 专业、可信、克制、温和，符合心理健康服务场景
- 避免医院式压迫感、过度警示色和娱乐化设计
- 管理人员能够快速发现待处理事项
- 咨询师能够快速完成预警接单、干预、预约、记录和结案
- 被测者能够安心、低压力地完成测评
- 桌面端、平板和手机端均可正常使用
- 支持简体中文、日语、英语
- 页面状态与后端业务状态严格一致
- 所有重要操作都有明确反馈、错误恢复和下一步指引

二、先做完整页面审查

请先扫描：

- 所有路由
- 页面组件
- 公共组件
- API 封装
- 权限组件
- 国际化资源
- CSS/主题配置
- 图表组件
- 表单和弹窗
- 移动端适配
- 加载、空状态、错误状态和无权限状态

输出页面矩阵：

| 页面 | 使用角色 | 核心任务 | 当前问题 | 优化方案 | 优先级 |
|---|---|---|---|---|---|

识别：

- 有路由但没有完整功能的页面
- 有接口但没有页面入口的功能
- 页面按钮存在但后端链路无法完成的功能
- 同一功能在多个页面重复实现的问题
- 用户不知道下一步做什么的问题
- 表格在手机端不可用的问题
- 弹窗关闭后业务状态丢失的问题
- 只有成功状态、没有失败恢复的问题
- 权限不一致导致按钮可见但接口返回 403 的问题

完成审查后直接实施优化。

三、角色化信息架构

不要让所有角色看到相同工作台。

1. 被测者

核心入口：

- 首页
- 待完成测评
- 已完成测评
- 我的报告
- 我的预约
- 通知
- 个人资料

首页重点展示：

- 最需要处理的一件事
- 待完成任务数量
- 最近截止任务
- 最近报告
- 即将到来的预约
- 未读通知

不要向被测者展示内部预警等级、内部处置状态、稳定键、数据库 ID 或技术字段。

2. 咨询师

核心入口：

- 今日工作台
- 待接单预警
- 我的处理中预警
- 今日预约
- 待填写咨询记录
- 复测跟踪
- 已结案记录

首页优先展示：

- P0/P1 待处理预警
- 即将超时的干预
- 今日预约时间线
- 待补充咨询记录
- 复测结果变化

3. 测评管理员

核心入口：

- 量表管理
- 量表导入
- 测评任务
- 分配与完成进度
- 群体报告
- 预警概览
- 导出中心

首页重点：

- 进行中任务
- 即将截止任务
- 完成率异常任务
- 导入失败记录
- 风险趋势
- 导出失败任务

4. 组织管理员/学校负责人

重点提供：

- 组织整体趋势
- 完成率
- 风险分布
- 时间趋势
- 组织对比
- 数据范围说明

默认显示聚合、脱敏数据，不直接暴露个人敏感信息。

5. 系统管理员

重点提供：

- 用户与角色
- 租户和组织
- 登录与安全事件
- 设备和会话
- 通知投递
- 导出任务
- 系统健康状态

四、被测者答题体验

重点重新设计答题页面：

- 一次聚焦一个问题
- 显示清晰但不过度强调的进度
- 支持上一题、下一题和题号导航
- 必答题明确标记
- 不使用带有责备感的错误提示
- 支持自动保存和手动保存
- 明确显示最近保存时间
- 网络中断时保存本地草稿并提示同步状态
- 版本冲突时提供恢复或重新加载选项
- 提交前显示未完成题目
- 提交期间禁止重复操作
- 提交超时时能够查询提交结果，不要求用户盲目重填
- 已完成任务不能再次进入空白答题页
- 允许重测时明确说明其影响
- 匿名任务明确告知匿名范围、用途和隐私限制
- 截止、超时、未开始、已关闭等状态提供明确说明

手机端按钮需要适合单手操作，主要操作固定在安全区域，不能被浏览器底部工具栏遮挡。

五、量表导入和编辑体验

将量表管理优化为清晰的业务流程：

导入文件 → 解析 → 字段映射 → 规则校验 → 预览 → 试算 → 确认导入 → 发布版本

要求：

- 提供可下载模板
- 支持拖拽上传
- 显示解析进度
- 错误定位到工作表、行、列和字段
- 区分错误与警告
- 可筛选、搜索和导出错误明细
- 导入失败不得只显示“请求失败”
- 显示题目、选项、维度、计分规则、常模和预警规则摘要
- 提供测试答案和预期得分试算
- 发布前显示完整检查清单
- 已被任务使用的版本必须只读
- 新建版本时明确展示与旧版本的差异
- 中日英量表内容能够并排检查缺失翻译

六、任务管理体验

优化任务创建与发布流程：

基本信息 → 选择已发布量表 → 时间规则 → 分配范围 → 通知设置 → 发布确认

需要：

- 量表选择器只显示可用的已发布版本
- 显示量表版本、题目数、预计用时和匿名支持情况
- 时间选择提供时区说明
- 明确展示是否允许保存、重测、超时提交
- 支持按用户、班级、部门和组织选择
- 显示预计覆盖人数
- 发布前确认通知接收人数
- 任务详情展示完成率、未开始、进行中、已完成和逾期人数
- 能够查看通知发送状态
- 关闭任务需要说明影响并二次确认
- 危险操作不能只依靠红色按钮区分

七、预警与干预工作台

不要只用普通表格展示预警。

需要提供：

- 按优先级分组
- 待接单、已分配、处理中、即将超时、已关闭
- P0/P1 视觉突出，但避免整页高饱和红色
- 显示剩余响应时间
- 支持快速接单和转派
- 操作后立即更新状态
- 可查看测评摘要和历史趋势
- 干预计划可保存草稿
- 关闭弹窗或重新登录后能够继续
- 预约、咨询记录、复测和结案形成时间线
- 结案前检查必要信息
- 完整展示操作人、时间和状态变化

敏感信息查看和导出必须有权限说明与审计提示。

八、预约与咨询记录

提供日历和列表两种视图：

- 今日
- 本周
- 待处理
- 已完成
- 已取消
- 已失约

支持：

- 创建预约
- 改期
- 取消
- 确认
- 标记失约
- 填写咨询记录
- 转介
- 创建复测
- 查看历史记录

咨询师默认看到分配给自己的预约，被测者默认看到自己创建的预约。

九、报告和图表

优化个人报告和群体报告：

- 图表必须有文字结论，不能只显示图形
- 明确数据范围、统计口径和更新时间
- 风险等级同时使用文字、颜色和图标，不能仅依赖颜色
- 图表支持中日英标签
- 手机端图表可滚动或重排
- 空数据、小样本和异常数据有明确说明
- 匿名群体报告显示最小样本保护提示
- 支持筛选、对比、趋势分析和导出
- 导出操作显示进度、状态、失败原因和重试入口
- 不允许用户通过导出任务 ID 下载无权限文件

十、中日英三语

支持：

- `zh-CN`
- `ja-JP`
- `en-US`

要求：

- 页面、菜单、按钮、表单、状态、验证提示、空状态、错误提示、通知和图表全部国际化
- 禁止在 JSX、TS 和 CSS 中硬编码自然语言
- 三种语言 key 必须完全一致
- 增加自动化测试验证翻译完整性
- 处理中文、日文和英文长度差异
- 按钮和表格列不能因为英文或日文变长而截断
- 使用各语言自然表达，不做生硬逐字翻译
- 专业心理学术语建立统一术语表
- 日期、时间、数字、百分比和时区按 locale 格式化
- 语言切换后当前页面和未提交表单状态不能丢失

十一、设计系统

建立统一设计 Token：

- 主色
- 成功、警告、危险、信息色
- 页面背景
- 卡片背景
- 文字层级
- 边框
- 阴影
- 圆角
- 间距
- 字号
- 行高
- 响应式断点

要求：

- 优先复用公共组件，不在页面中复制样式
- 统一页面标题、筛选区、数据卡片、表格、弹窗和表单布局
- 深色文字必须满足可读性
- 颜色对比度符合 WCAG AA
- 支持键盘操作和可见焦点
- 表单控件有可访问标签
- 图标不能代替所有文字
- 尊重 `prefers-reduced-motion`
- 动画简洁，不影响紧急业务操作

推荐视觉方向：

- 温和的蓝绿色或低饱和蓝色作为主色
- 大面积浅色中性背景
- 风险颜色只用于必要区域
- 适度圆角和轻阴影
- 信息密度根据角色调整
- 避免过度渐变、玻璃拟态、超大标题和装饰性动画

十二、页面状态完整性

每个数据页面必须实现：

- 首次加载状态
- 局部刷新状态
- 空状态
- 筛选后无结果
- 请求失败
- 权限不足
- 会话过期
- 后端业务冲突
- 保存成功
- 部分成功
- 重试入口

禁止：

- 空白页面
- 永久转圈
- 只在控制台打印错误
- 把后端异常代码直接显示给普通用户
- 操作成功后页面仍显示旧状态
- 关闭弹窗后丢失不可恢复的业务上下文

十三、性能

检查并优化：

- 路由懒加载
- 大型图表按需加载
- Ant Design 和 ECharts 打包体积
- 大表格分页或虚拟滚动
- React Query 缓存和失效策略
- 重复请求
- 不必要的全页面刷新
- 图片体积
- 首屏加载
- 移动网络下的交互体验

不要通过删除必要功能来降低包体积。

十四、验证要求

完成后必须执行：

- TypeScript 类型检查
- 前端全部测试
- 生产构建
- 中日英翻译完整性测试
- 主要页面组件测试
- 权限与角色组合测试
- 移动端响应式检查
- 键盘操作检查
- WCAG 对比度检查
- 浏览器端到端测试

至少验证：

1. 中文、日语、英语分别完成一次登录、答题、报告查看和预约。
2. 管理员完成量表导入、发布任务和查看完成率。
3. 咨询师完成预警接单、干预、预约、咨询记录、复测和结案。
4. 手机宽度下完成整个答题流程。
5. 网络失败后恢复草稿并继续提交。
6. 没有权限的角色看不到操作入口，直接访问也被阻止。
7. 页面刷新后正在处理的干预和导出任务仍可恢复。
8. 三种语言下无文字溢出、重叠或未翻译 key。

十五、实施约束

- 先输出页面审查结果和改造优先级，然后直接修改代码
- 优先修复业务流程断点，再统一视觉
- 保持现有 API-backed 功能
- 不使用假数据代替真实接口
- 不把后端权限校验移到前端
- 不修改无关业务逻辑
- 所有修改都必须有真实构建或测试证据
- 完成后列出修改文件、页面截图、测试结果和未完成项

最终分别说明：

- 哪些页面只是视觉优化
- 哪些页面修复了业务闭环
- 哪些页面仍受后端接口限制
- 是否达到可演示、可验收、可上线三个不同等级
```
