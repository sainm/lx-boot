在不破坏现有 API、历史 PostgreSQL 数据、多租户边界、匿名隐私、审计和中日英能力的前提下，关闭以下剩余工作：

4. 建立真实性能、容量、可观测性和外部依赖故障恢复基线。

### 一、强制原则

1. 每批先扫描和测量，列出文件、迁移、API、数据影响、风险与回滚，再修改。
2. 不删除、重建或自动清空现有 PostgreSQL 数据，不对 `lx/public` 自动 baseline。

5. 不破坏现有 API；新增字段优先保持可选，破坏性变化必须提供版本化迁移期。

1. 保持现有受控 ScalePackage preview/confirm、逐项错误、三语缺失、引用冲突、授权缺失、源 ID 重映射、审批重置、原子领取和 PostgreSQL 完整落库能力；现有 Playwright 自动化回归覆盖真实浏览器上传/预览/确认与匿名、角色、租户矩阵，后续必须保留在 CI。导入成功不等于允许发布。
2. 保持 schema v1 导入兼容以及 schema v2 ScalePackage 导出的摘要可验证性；控制器跨租户不可见、真实浏览器下载及租户安全审计已验证，把该 Case 固化为自动化回归。在 G5 测量后决定容量上限或流式化方案，不得把当前内存导出宣称为大文件能力。
3. 保持已验证的真实 PostgreSQL/浏览器内容失效 Case：完整证据达到 ready 后修改题目，六类旧 Case 必须全部标记 stale，旧双审核只能保留为追加式历史且不能匹配新发布指纹；Web 必须继续用中日英说明需要新 revision、重跑和重审。后续如增加可编辑算法配置，再补算法变化的同等 Case。
4. 对现有结构化编辑与历史页补组件/浏览器测试，验证三语字段、JSON 校验、草稿保存、已发布版本只读、坏历史证据错误恢复以及没有凭空补写翻译或授权事实。
5. 保持已验证的同租户六类 run/approve、不同用户双审核、publish、已发布只读、跨租户 readiness 404 和任务版本摘要锁定；继续为列表、详情、保存、history 以及对象不存在补齐尚缺的角色矩阵，并以真实量表重跑同一发布链。
6. 选取一份已获授权的真实简单量表录入实际中日英内容、来源、授权、常模/阈值和 Golden Case；模型或开发人员生成的内容只能标为 `NEEDS_REVIEW`，不能代替专业或法务结论。

外部输入不能由代码代理编造：

- 心理专业人员提供并审核正式题目、计分规则、常模、解释、风险规则和 Golden Case。
- 法务确认版权、翻译权、常模授权、地域、用途和有效期。
- 业务负责人确认适用流程、结果可见范围、审批分工和高风险响应责任。

验收：至少选择一份已获授权的简单量表，在中日英三种语言下完成“录入/导入 -> preview -> Golden Case -> 双审批 -> 发布 -> 任务锁定版本 -> 评分追溯”的真实 E2E。没有外部签审时状态最多为 `TECHNICALLY_VERIFIED`。

### 四、目标 G2：面向大多数量表的计分与题型能力

不得一开始就实现任意脚本引擎。先建立目标量表清单并逐份记录：题型、维度、缺失策略、常模、效度、公式、风险规则、版权和审核状态，然后按真实需求实施。

优先补齐通用能力：

1. 一题参与多个维度，并能审计每个维度的权重和中间分。
2. `ALLOW`、`PRORATE` 等缺失策略、最大缺失率、无法评分和无效答卷结果。
3. 最短/最长作答时长、矛盾答案、一致性和反应模式效度规则。
4. 分段换算、百分位、条件公式和明确的常模选择优先级/无匹配结果。
5. `NUMBER`、`RANKING`、完整 `MATRIX`、跳题和显示条件；文本默认不计分。
6. 可审计评分轨迹：原始答案映射、反向分、权重、维度分、缺失处理、效度结果、常模选择、标准分和解释规则。
7. 有版本、白名单、纯计算且不能访问数据库/文件/网络的专用算法扩展点；算法超时或异常返回稳定错误，不产生部分结果。
8. 每种能力都有正常、边界、反向、缺失、无效和高风险 Golden Case。

适配状态必须按量表而不是按系统笼统声明：

- `FULLY_SUPPORTED`：正式手册、授权内容/常模、三语、算法、Golden Case、双审批和 E2E 全部完成。
- `TECHNICALLY_SUPPORTED_PENDING_REVIEW`：技术和测试完成，等待专业或法务审核。
- `PARTIALLY_SUPPORTED`：只有部分题型、维度、常模或解释。
- `UNSUPPORTED`：运行引擎不支持，发布必须被阻止。

PHQ、GAD 等简单累加量表可以优先作为通用引擎验证样例；SCL、EPQ、16PF、MMPI 等必须依据正式手册实现专用维度、效度、常模和解释。无授权数据和专业验证时不得宣称正式支持。

验收：输出逐量表能力矩阵；每个 `FULLY_SUPPORTED` 量表必须有来源、授权、算法版本、三语完整性、六类 Golden Case、双审批和真实 PostgreSQL E2E 证据。

### 六、目标 G4：租户约束、匿名安全与真实 E2E
