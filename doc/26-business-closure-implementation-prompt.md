# 心理测评业务闭环实施 Prompt

## 使用说明

将下面代码块中的内容完整复制给 Codex、GitHub Copilot 或其他代码代理，用于从业务角度审查和完善心理测评系统。该 Prompt 强调真实业务闭环、中日英三语、多租户安全和运行验证。

```textå
请从真实心理测评业务角度，全面审查并完善当前工程。

目标不是单纯修复编译错误，而是确保以下业务形成可运行、可验证、可追踪的完整闭环：

量表导入 → 量表校验 → 发布版本 → 创建任务 → 分配用户/组织 → 中途保存 → 提交答卷 → 自动评分 → 风险预警 → 接单干预 → 咨询预约 → 咨询记录 → 复测 → 结案 → 个人/群体报表 → 导出与审计。

一、量表兼容能力

系统需要支持导入多种常见心理评测量表，不能针对单一量表写死。

至少支持：

- PHQ-9、GAD-7、SDS、SAS、SCL-90、PSS、WHO-5 等常见量表
- 单选、多选、文本、滑块、矩阵、选项加文本等题型
- 正向计分、反向计分、分段计分、加权计分
- 总分、维度分、原始分、标准分、Z 分、T 分
- 不同性别、年龄、年级、组织等常模匹配
- 高风险单题触发、总分阈值触发、维度阈值触发、组合条件触发
- 匿名量表与实名量表
- 量表版本管理，历史任务必须固定原始版本，不能被后续修改影响

导入必须包含：

- 预览
- 字段映射
- 格式和业务规则校验
- 错误行、字段、原因反馈
- 原子性写入，失败时不能产生半成品
- 重复导入与版本冲突处理
- Excel/CSV/JSON 模板和示例
- 导入后可立即进行试算验证

二、测评任务闭环

检查并实现：

- 只能使用已发布量表创建任务
- 支持按用户、班级、部门、组织分配
- 分配后通知所有实际接收者
- 严格执行开始时间、结束时间和任务状态
- `allowSaveFlag`、`allowRetakeFlag`、`allowTimeoutSubmitFlag` 必须真实生效
- 草稿支持多端恢复、版本冲突检测和过期清理
- 提交必须幂等，重复提交不能生成重复报告或预警
- 匿名测评不得进入个人报告、个人预警、咨询和干预链路
- 匿名答卷不得直接保存可识别用户身份，只能进入群体统计
- 已开始任务使用不可变的量表版本快照

三、评分、预警与干预

评分结果必须可解释、可复现，保存使用的量表版本、规则版本、常模和计算过程。

预警至少支持：

- 高风险答案即时预警
- 总分、维度分和组合规则预警
- P0/P1/P2 等优先级
- 待接单、已分配、处理中、已关闭状态
- 未接单超时升级
- 处理中超时提醒
- 无负责人时通知租户内值班咨询师或管理员
- 通知失败重试和运维查询
- 预警访问严格限制在当前租户和授权数据范围内

干预闭环必须支持：

- 接单和转派
- 创建干预计划
- 关闭页面或重新登录后继续处理
- 咨询预约
- 咨询师查看分配给自己的预约
- 取消、改期、失约、完成
- 咨询记录
- 转介
- 创建复测任务
- 结案及结案说明
- 完整状态日志和审计记录

四、报告与统计

个人报告支持：

- 总分、维度分、风险等级、结果解释和建议
- 图表展示
- 量表版本与评分依据
- 查看和导出审计
- 数据脱敏
- 严格的本人、角色、租户和数据范围权限

群体报告支持：

- 按任务、组织、班级、部门、时间和量表筛选
- 完成率、分数分布、风险分布、趋势和维度分析
- 匿名数据最小样本量保护
- 小样本不得反推出个人
- 多次测评趋势比较
- PDF、Word、Excel/CSV 导出
- 异步导出任务必须记录创建人、租户、来源、重试次数和状态
- 用户只能查看和下载自己有权访问的导出结果

五、中日英三语

所有面向用户的自然语言必须支持：

- 简体中文：zh-CN
- 日语：ja-JP
- 英语：en-US

覆盖范围包括：

- Web 管理端
- Web 被测者端
- Android
- 登录、注册、邮件和通知
- 表单标签、按钮、状态、错误提示
- 量表导入提示和错误明细
- 预警、干预和预约
- 报告标题、解释、建议和导出文件
- 后端业务异常
- Push、邮件及站内信模板
- 日期、时间、数字和文件名

要求：

- 不允许在组件或业务代码中硬编码中文、日语或英语
- 三种语言的 key 必须完全一致
- 缺失翻译时测试失败，不能静默显示 key
- 保留命令、路径、URL、代码标识符、字段名和协议值，不要翻译
- 语言选择需要持久化并随请求传到后端
- 后端异步任务必须保存创建时的 locale
- 量表内容本身支持多语言版本或翻译字段
- 不允许用机器翻译结果覆盖专业心理学术语，专业文案需要标记为待业务审核

六、安全和多租户

检查所有查询和对象访问，不能只依赖角色名称。

必须验证：

- 当前用户
- 当前租户
- 组织/班级数据范围
- 对象所有者
- 业务状态
- 匿名数据限制

重点检查报告、预警、任务、答卷、干预、预约、统计、通知和导出，防止通过 ID 访问其他租户数据。

Token、草稿和敏感答案不得以明文长期存储在普通 localStorage 或 SharedPreferences 中。

七、验证要求

不要只做静态检查。修改完成后必须执行：

- 后端全部单元测试
- PostgreSQL 集成测试
- 前端全部测试和生产构建
- 中日英翻译目录一致性测试
- 关键页面组件测试
- Android Debug 构建和测试
- 浏览器端到端业务测试
- 多租户越权测试
- 匿名测评隐私测试
- 任务时间边界测试
- 重复提交和并发提交测试
- 预警超时升级测试
- 通知失败重试测试
- 导出对象授权测试

至少验证以下真实 Case：

1. 导入 PHQ-9，发布后创建任务并分配用户，完成答题、评分和个人报告。
2. 导入包含反向计分、维度和常模的量表，确认计算结果正确。
3. 高风险单题提交后立即创建预警并通知负责人。
4. 未接单预警超时后升级并通知值班人员。
5. 咨询师接单、预约、填写记录、创建复测并结案。
6. 匿名任务只产生受最小样本量保护的群体统计。
7. 截止后根据 `allowTimeoutSubmitFlag` 正确允许或拒绝提交。
8. 不同租户无法互相查看报告、预警、预约和导出文件。
9. 同一流程分别使用中文、日语、英语执行，页面、通知和报告语言正确。
10. 同一提交请求重复发送时只生成一份结果。

八、交付方式

先输出：

- 当前业务功能矩阵
- 已闭环、部分闭环、未实现和实现错误的功能
- P0/P1/P2 问题清单
- 涉及文件和修复方案
- 数据库迁移影响
- 测试计划

然后直接实施修复。

完成后报告：

- 实际修改文件
- 已通过的 Case
- 未通过或未验证的 Case
- 测试和构建结果
- 剩余风险
- 是否达到可验收、可部署、可上线三个不同级别

不要因为已有页面、接口或数据表就判断功能已完成。只有业务主流程、异常流程、权限、状态、通知、审计和测试全部接通，才算真正闭环。
```
