# 手动测试手顺（完整版）

## 0. 文档说明

| 项目 | 内容 |
| --- | --- |
| 文档用途 | 交付前由测试人员按步骤手工验证系统主链路、权限边界、三语、数据一致性与运维能力 |
| 代码基线 | 分支 `feature/redo`，HEAD `f178857`（2026-09-19） |
| 事实来源 | `doc/13-api-design-detailed.md`（109 条业务路径 + 54 条认证路径）、`admin-web/src/app/route-config.tsx`（页面与角色）、`backend/src/main/resources/data-psy.sql`（种子数据）、`doc/10-database-table-design.md`（V1–V28 实际结构） |
| 结构基线 | Flyway `V1–V28`，61 张表（46 `psy_*` + 15 `sys_*`） |
| 执行方式 | 按章节顺序执行；`P0` 用例必须全部通过，`P1` 不允许存在未关闭的高影响缺陷，`P2` 允许记录后延期 |
| 通过判定 | 实际结果与“期望结果”一致，且截图、SQL 输出或响应体证据已保存 |

**重要边界**

- 种子账号、`STRESS_DEMO`、`SCL90_TECH_DEMO` 等均为技术夹具，不代表量表版权、授权、常模、三语审校、专业双审批或临床可用性。
- 手动测试发现的任何“技术通过”不得写成“正式支持/临床可用”。
- 生产环境禁止使用本文的开发种子、默认口令与 `PSY_SQL_INIT_MODE=always`。

### 0.1 用例编号与优先级

- 编号规则：`MT-<模块>-<三位序号>`，例如 `MT-AUTH-001`。
- `P0`：主链路或安全边界，失败即阻塞交付。
- `P1`：重要分支、异常处理、数据一致性。
- `P2`：体验、兼容性、低频场景。

### 1.6 通过标准

1. `P0` 用例 100% 通过。
2. `P1` 用例通过率 ≥ 95%，未通过项必须有缺陷编号与临时规避说明。
3. 数据库无孤儿行、无跨租户数据、无重复当前结果。
4. 三语界面无枚举码直显、无未翻译空白。
5. 所有 `4xx/5xx` 均返回统一错误信封，日志不泄露口令、令牌与答案明文。

## 3. 认证、注册与账号（MT-AUTH）

### 3.1 登录与会话（P0 全流程）

#### MT-AUTH-001 用户名密码登录（详细步骤）

1. 打开 `http://127.0.0.1:5173/login`。
2. 语言保持“中文”，账号输入 `assessor`，密码输入 `ChangeMe123`。
3. 点击“登录”。
4. 若页面出现角色选择，选择“测评管理员”（ASSESSMENT_ADMIN）。
5. 刷新页面一次，确认会话保持。
6. 查看浏览器开发者工具 Network：`POST /auth/login/password` 成功，`GET /auth/me` 返回当前用户。

期望：进入管理端；菜单包含仪表盘、量表管理、量表发布就绪、量表治理录入、测评任务、预警管理、安全响应策略、群体报告、个体报告管理、预约咨询、导出中心、通知消息、会话详情、待审核注册；不含“用户管理”“认证审计”。

证据：登录成功截图、`/auth/me` 响应、菜单截图。

#### MT-AUTH-002 错误口令与失败提示

1. 用 `assessor` + 错误口令连续登录 3 次。
2. 第 4 次使用正确口令登录。

期望：错误提示为本地化文案，不暴露账号是否存在；达到锁定阈值后提示锁定；后续正确口令在锁定期内仍被拒绝。保存响应与提示截图。

#### MT-AUTH-003 禁用账号拒绝登录

1. 用 `org_manager` 登录，打开“用户管理”，把 `respondent` 禁用。
2. 用 `respondent/ChangeMe123` 登录。
3. 测试完成后重新启用该账号。

期望：禁用账号登录被拒绝；提示不泄露内部状态；`sys_login_log` 记录拒绝原因。

```sql
select principal, login_type, result, reason, created_at
from sys_login_log where principal = 'respondent' order by created_at desc limit 5;
```

#### MT-AUTH-004 刷新令牌与会话保持

1. 登录后等待访问令牌过期时间附近（或缩短本地配置后重试）。
2. 刷新页面，观察是否自动调用 `POST /auth/token/refresh`。

期望：无需重新登录即可继续访问；刷新失败时回到登录页并清除本地令牌。

#### MT-AUTH-005 退出登录

1. 点击右上角用户菜单，“退出登录”。
2. 浏览器后退到工作台页面。

期望：返回登录页；后退不能恢复会话；`POST /auth/logout` 成功；本地令牌被清除。

## 13. 预警、干预与安全响应策略（MT-WARN）

### 13.1 高风险预警闭环（P0 全流程）

#### MT-WARN-001 预警识别与列表

1. 用 `campus_assessor` 或 `campus_counselor` 打开“预警管理”。
2. 按等级“高风险”、状态“已指派”筛选。
3. 查看列：预警编号、结果编号、等级、优先级、状态、触发原因、安全响应策略、首次响应截止、创建时间。

期望：能看到校园高风险种子预警（`ASSIGNED`、P1）；策略列显示已绑定版本或“缺少已审批策略”；供应商/跨租户预警不可见。

#### MT-WARN-002 接单

1. 对一条“待处理”预警点击“接单”并确认。

期望：提示“预警已接单”；状态变为处理中/已接单；`first_response_time` 写入；操作写审计；重复接单不产生重复记录。

#### MT-WARN-003 指派

1. 用 `campus_assessor` 点击“指派”，在责任人下拉框中搜索并选择本租户工作人员（下拉来自 `GET /warnings/assignee-options`，只返回本租户在职人员）。
2. 再用其他租户的用户 ID 调用 `POST /warnings/{id}/assign` 重复一次。

期望：本租户指派成功并生成通知；跨租户被拒绝（`WARNING_ASSIGNEE_FORBIDDEN`）；预警列表的“责任人”列显示被指派人姓名，未指派显示“未指派”；操作列保持“接单 / 指派 / 报告页 / 更多（导出、干预记录）”结构。

#### MT-WARN-004 报告与导出

1. 点击“报告页”跳转到关联报告详情。
2. 点击“导出”，分别导出文本与 PDF。

期望：报告归属正确；导出文件可打开；导出行为写审计；跨租户导出返回 404。

#### MT-WARN-005 干预记录创建与结案

1. 点击“干预记录”，填写计划文本（或调用 `POST /api/v1/interventions`）。
2. 结案时调用 `POST /api/v1/interventions/{id}/close`，填写结案摘要；勾选“需要复测”并绑定复测任务。

期望：干预记录 `PROCESSING → CLOSED`；状态流水保留；复测任务回填 `retest_task_id`；结案需摘要，空摘要被拒绝。

#### MT-WARN-006 安全响应策略双人审批（详细步骤）

1. 用 `campus_assessor` 打开“安全响应策略”，点击“新建策略版本”。
2. 填写策略编码、版本、风险级别（如 P1）、首次响应/升级/随访分钟数、责任角色、备份角色、机构紧急联系说明，保存。
3. 用 `campus_counselor` 登录，对同一策略（或调用 `POST /api/v1/safety-response-policies/{id}/professional-review`）填写心理专业审核人 ID，提交专业审核。
4. 用 `campus_assessor`（与审核人不同的管理员）点击“双重审批并启用”。
5. 尝试用与专业审核人相同的用户执行审批。

期望：步骤 3 记录 `professional_reviewer_id` 与 `professional_reviewed_at`；步骤 4 策略 `status=APPROVED`、`active_flag=true`；步骤 5 被拒绝并提示双人分离；未复核策略不能启用。

```sql
select policy_code, version_no, status, active_flag,
       professional_reviewer_id, approved_by,
       professional_reviewed_at, approved_at
from psy_safety_response_policy
where active_flag order by id desc;
-- 期望：professional_reviewer_id is not null、approved_by is not null、
--       两个 id 不相等、两个时间均不为空
```

| 登录提示无账号 | 是否已执行 `data-psy.sql`、账号是否被禁用 | 用 `PSY_SQL_INIT_MODE=always` 重新导入；查询 `sys_user/sys_auth` |
| 量表列表为空 | 当前账号租户是否与种子租户一致 | 用 `assessor`（DEFAULT）确认；跨租户不可见是预期 |
| 无法发布量表 | 发布就绪阻塞项 | 按就绪页逐项补齐治理、三语、Golden Case、双审核 |
| 任务列表看不到新任务 | 状态、分配目标、租户 | 草稿任务分配后被测者可见；检查 `psy_assessment_task_assignment` |
| 提交被拒绝 | 任务状态、截止时间、质量策略、必答题 | 检查 `error.*` 业务码；必要时提高缺失策略或调整时间 |
| 预警策略显示缺失 | 是否存在 `active_flag=true` 且双人审批完成的策略 | 走第 13 章双人审批流程；不得手工伪造审批人 |
| 导出一直 PENDING | worker 配置与对象存储可达性 | 查看导出中心存储配置与 `/actuator/prometheus` 队列指标 |
| 通知一直 PENDING/FAILED | 渠道配置、租约超时、最大重试次数 | 检查策略、SMTP/Push 配置、`processing_started_at`、死信记录 |
| 迁移失败 | Flyway history、advisory lock、失败迁移 | 前滚修复或恢复备份；禁止 `clean`、禁止改已执行迁移 |
